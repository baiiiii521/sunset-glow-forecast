# 霞（GLOW）服务端缓存与定时任务部署说明

## 这套东西解决什么

| 问题 | 解法 | 位置 |
|---|---|---|
| 每个访客每次刷新都直接打 Open-Meteo，容易 429 | nginx `proxy_cache` 缓存 10 分钟 | `deploy/nginx-glow-cache.conf` |
| 不想动 nginx，或要按城市做更细的缓存 | 30 行 Node 代理 | `deploy/cache-proxy.js` |
| 接口挂了页面全空 | 前端回落每小时快照 `data/snapshots.json` | 已内置 |
| 霞榜城市太少 | 两段式扩容（粗筛 850 城 → 精算 100 城 → 取前十） | `scripts/build-rankings-v3.js` |
| 热门前 200 城要秒开 | 每小时快照 | `scripts/build-snapshots.js` |

## 一、启用缓存代理（二选一）

### A. nginx（推荐，零进程）

1. 把 `deploy/nginx-glow-cache.conf` 里的 `proxy_cache_path` 与两个 `location` 粘进站点 server 块。
2. 在 v2 三个页面 `<head>` 里、**加载 `../api.js` 之前**加一行：

```html
<script>window.GLOW_OM_BASE = '/om';</script>
```

3. `nginx -t && systemctl reload nginx`。

之后浏览器的请求变成 `https://你的域名/om/v1/forecast?...`，nginx 缓存 10 分钟；同一城市 10 分钟内只回源一次。

### B. Node 代理（没有 nginx 配置权时）

```bash
node deploy/cache-proxy.js 8790
```

然后 nginx 加一条反代：`location /om/ { proxy_pass http://127.0.0.1:8790/; }`，同样设 `window.GLOW_OM_BASE='/om'`。

## 二、定时任务

```cron
# 每天 15:00（北京时间）重算霞榜：粗筛 850 城 → 精算 100 城 → 取前十
0 15 * * * cd /var/www/glow && /usr/bin/node scripts/build-rankings-v3.js --global 500 --china 350 --top 50 >> /var/log/glow-rankings.log 2>&1

# 每小时刷新热门 200 城快照（首屏秒开 + 降级兜底）
7 * * * * cd /var/www/glow && /usr/bin/node scripts/build-snapshots.js 200 >> /var/log/glow-snapshots.log 2>&1
```

两个脚本都是「先写 .tmp 再 rename」，网页不会读到半份文件；有效城市太少会直接失败并保留旧文件。

## 三、请求量估算（免费额度 10,000 次/天）

| 任务 | 请求数 |
|---|---|
| 霞榜粗筛 850 城（6 城/请求 × 2 接口） | ≈ 284 |
| 霞榜精算 100 城（每城 3 请求） | ≈ 300 |
| 每小时快照 200 城 × 24 次 | ≈ 1,600 |
| 合计 | ≈ 2,200/天 |

剩下 7,800 次留给真实访客；再叠加 nginx 10 分钟缓存，实际可支撑数万次浏览。

## 四、429 降级行为

- 城市页：先用 `data/snapshots.json` 画一版（标注「快照 HH:MM」），实时数据到了再替换。
- 接口失败：保留快照并在顶部显示「接口限流或超时，先显示每小时快照」。
- 霞榜页：`rankings.json` 超过 36 小时会在顶部亮黄条「非今日」，不会假装是今天的数据。

## 五、额度真相（2026-10-24 实测踩到 429 后修正）

Open-Meteo 免费档按**坐标数**计调用：一次请求 24 个坐标 = 24 次调用。
限制约为 **600 次/分钟、5,000 次/小时、10,000 次/天**（非商用）。

所以原来设想的「每小时 200 城快照」不可行：

| 方案 | 每次运行调用 | 频率 | 每天 |
|---|---|---|---|
| 快照 200 城 × 6 坐标 × 2 接口 | 2,400 | 每小时 | 57,600 ❌ |
| 快照 80 城 × 4 坐标 × 2 接口 | 640 | 每小时 | 15,360 ❌ |
| 快照 20 城 × 4 坐标 × 2 接口 | 160 | 每小时 | 3,840 ✅ |
| 霞榜粗筛 500 城 × 4 坐标 × 2 接口 | 4,000 | 每天 | 4,000 ✅ |
| 霞榜精算 60 城 × 11 次 | 660 | 每天 | 660 ✅ |

**免费档可行组合**：霞榜 500 城（4,660/天）+ 热门 20 城每小时快照（3,840/天）≈ 8,500/天，剩 1,500 次给访客；配合 nginx 10 分钟缓存，实际可支撑上万次浏览。

**要真正「每小时 200 城」**：需要 Open-Meteo 付费档（约 €29/月起，100 万次/月），那时 57,600/天也扛得住。

## 六、脚本已内置的限流

`scripts/lib/score-batch.js` 里有分钟级闸门（默认 420 次/分钟，`GLOW_RATE_PER_MIN` 可调），按坐标数计费，超了自动等，避免再次打出 429。
粗筛把上游点从 5 个减到 3 个（50/150/300km），省 40% 调用。
