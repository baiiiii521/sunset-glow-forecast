# 视觉元素拆解（visual-element-breakdown）

> 分类：**A = 纯代码**（布局/渐变/文字/图标/图表/动画）、**B = 独立图片**、**C = 代码 + 图片**
> 判定标准：能用 CSS/SVG/Canvas 精确还原的，一律归 A；只有「真实摄影级天空/环境」才归 B。

---

## 全局统计

| 类 | 元素数 | 占比 | 说明 |
|---|---|---|---|
| A 纯代码 | **187** | 93% | 布局、排版、色阶、图表、图标、动效、地图矢量 |
| B 独立图片 | **1 类 / 12 张** | 5% | 天幕底图（6 档 × 朝晚） |
| C 混合 | **2** | 2% | ① 首屏天幕 + 遮罩 + 数据层 ② 分享卡（底图 + 实时数字） |

关键结论：**这是一套「代码驱动」的设计**，生图只负责「天」，其余全部由组件与图表渲染。任何把整块 UI 做成图片的做法都不成立。

## 明确「不要生图」的清单

以下看似可以用图，但必须代码实现，否则失去响应式与数据联动：

| 元素 | 为什么必须代码 |
|---|---|
| 分数环 / 等级条 | 跟随数值变化 |
| 七日矩阵色块 | 7×3 数据驱动 |
| 云层剖面 | 由 cloud_cover 实时改阈值 |
| 日落时序 8 格 | 由太阳高度实时渲染 |
| 地图与城市点 | 缩放、hover、点击联动 |
| 分享卡 | 每次查询的分数/城市都不同 → Canvas 绘制 |
| favicon / 印章 | 纯几何，SVG 即可 |
| 颗粒纹理 | CSS/SVG `feTurbulence`，无需位图 |

## B 类唯一主角：天幕

| 用途 | 文件 | 优先级 | 说明 |
|---|---|---|---|
| 首屏 + 城市页头 + 分享卡底图 | `sky-{dusk,dawn}-L0..L5.jpg` | **P0** | 6 档 × 2 态；按分数切换 |
| 备用（未用） | `spot-*.jpg` | — | 观景点功能已砍，留档 |

天幕的「混合（C）」实现要点：

```
[底图] → filter: saturate(.86) contrast(1.03) brightness(.92)
      → 遮罩：100deg 左向渐变（左 46% 由 .86 降到 0）
      → 底部径向暗角
      → 颗粒层（10% overlay）
      → UI（代码）
```

## 结论

- **A 类 93%**：开发主体是组件与图表，不是拼图。
- **B 类只有 12 张天幕**：这是唯一必须由 Codex CLI 生成的原创新素材。
- **C 类 2 处**：首屏天幕合成、分享卡。
