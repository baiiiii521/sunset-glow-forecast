# 01 · 现有网站审计（PHASE 01）

> 审计对象：https://glow.byb521.com/（线上）
> 审计时间：2026-10-23
> 证据来源：线上资源逐文件 md5 比对、1440×900 / 390×844 实机截图、源码通读、真实 API 结果、对比度计算
> 结论口径：只写能复现的事实；推断会标注「推断」。

---

## 0. 一句话结论

这是一个**气质已经很强、但产品完成度只在 60%** 的单页站：品牌记忆点（霞、六档命名、程序化天幕、诚实的算法叙事）比大多数同类产品都强，但它既不是「3 秒给出决策」的工具，也不是「值得专程来看」的作品——它卡在中间。重构的价值不在换皮，而在**把天幕从背景变成仪器**，并让首屏直接回答「今晚、几点、去哪、值不值得」。

### 2.2 信息层级与导航逻辑

当前导航是**章节导航**（01 霞历 / 02 天色 / 03 霞榜 / 04 剖面 / 05 原理），不是**任务导航**。

- 用户来这里的任务是：今晚会不会烧 → 几点 → 我去哪儿看 → 凭什么信。
- 当前导航给的是：霞历 / 天色 / 霞榜 / 剖面 / 原理——五个词都是产品内部概念，新用户无法预测点进去会得到什么（审计截图确认：实际点「03 霞榜」看到的是时间轴，因为锚点位置与 sticky 头部重叠，见 §5.3）。
- 结果：**任务与导航不同构**。用户必须先把整页滚完，才能自己拼出答案。

## 3. 视觉审计

### 3.1 做得好的（必须保留）

1. **程序化天幕**：SVG `feTurbulence + feDiffuseLighting` 生成的分形云被自下而上点亮，阈值与光色由分数/太阳高度实时改写——这是全站最有价值的原创资产，比任何图库照片都更「真」，也是品牌差异化的根。
2. **六档命名**：无烧 / 微烧 / 小烧 / 小到中烧 / 中到大烧 / 大烧。中文语感极好，比 1–5 星或百分比更有传播力。
3. **诚实叙事**：页面明写「这是启发式算法，不是官方预报」「缺数据就写无数据」「分档是待照片校准的操作定义」。这种克制是高级感的来源。
4. **竖排装饰字 + 印章式 logo**：「霞」字方块 + vertical-rl 的大字，是真正有识别度的东方编辑设计语言。
5. **技术底子**：对比度在纯色底上全部达标（cream 16.95:1、muted 9.14:1、dim 6.40:1、ember 6.31:1、gold 12.44:1）；已有 skip link、`aria-*`、`prefers-reduced-motion`。

### 3.2 具体问题（按严重度）

| 严重度 | 问题 | 证据 |
|---|---|---|
| 🔴 高 | **首屏不回答「今天」**：21:16 打开时首屏给的是「明日朝霞 05:43」，页面上没有「今天/明天」「晚霞/朝霞」的显式状态切换，用户极易误读 | 实机截图 + `app.js` 自动跳日逻辑 |
| 🔴 高 | **装饰压过信息**：城市名 132px、分数 300px、竖排「小烧」240px，而真正决定行动的「17:32 日落」「05:43」只有 12–14px | `styles.css:147/165/177` |
| 🔴 高 | **中文搜不到城市**：搜索框 placeholder 写「南阳 / 京都 / 巴黎」，但 Open-Meteo geocoding 对中文名返回空（实测 `name=胡志明` → `{"generationtime_ms":0.17}` 无 results；`name=Ho Chi Minh` → 正常）。用户第一动作就会失败 | API 实测 + 浏览器实测「未找到该地点」 |
| 🟠 中 | **导航词不可预测**：霞历/天色/霞榜/剖面/原理是内部词汇，且锚点跳转被 sticky header 遮挡（实测点 03 落在时间轴） | 截图 + `scroll-margin` 缺失 |
| 🟠 中 | **霞榜地图缺 Y 轴语义**：只标 80°E / 130°E，纵轴是什么（纬度？时区？）没有说明；相邻城市标签重叠（合肥/北京/苏州） | 截图 |
| 🟠 中 | **小字在照片上不可读**：经纬度、拉取时间、底部气象依据压在动态云层上，1–2 处已接近不可辨 | 截图 |
| 🟠 中 | **一个颜色承担不了六个等级**：ember (#FF5A1F) 只出现在 logo 和零星数字，42 分本身没有色阶编码，用户无法一眼判断高低 | CSS `:root` 仅 2 个色相 |
| 🟡 低 | **语义重复**：右侧竖排「小烧」与左侧「有一点·小烧」重复，占用黄金版面 | HTML |
| 🟡 低 | **胶囊语义混杂**：「收藏此地」（操作）与「明日朝霞 05:43」（信息）同形同重 | HTML |
| 🟡 低 | **缺滚动引导**：首屏没有下一屏暗示，长页靠用户自己探索 | 截图 |

### 3.3 字体与排版

- 三套字体：Noto Serif SC（900 display）、JetBrains Mono（数据/元信息，31 处）、Instrument Serif（斜体点缀，3 处）。
- 字号全部用 `clamp()`，desktop 上限偏大（132 / 300 / 240 px），缺少 720–1280px 之间的中间档；**全站只有 1 个断点（720px）**，平板宽度直接落到桌面或手机的极端值。
- 行宽：正文 `sec-lede` 约 60–70ch，合格；但 `.reason`、`.hero-facts` 在 900px 高视口下贴底（截图已压边）。

### 3.4 动效

- 已有：云层漂移（CSS keyframes）、数字滚动、时间轴播放、滚动入场。全部为 CSS 驱动，无滚动驱动（scroll-driven）编排，无页面级过渡（因为是单页）。
- 问题：动效是**均匀铺开的**，没有节奏——首屏与第 5 屏的出场动画强度一样，导致「第一眼不够炸，后面又嫌吵」。

## 4. 交互与功能缺陷

| # | 缺陷 | 影响 |
|---|---|---|
| 1 | 无 URL 状态（无 `?city=` / `#/city/ho-chi-minh`） | 无法分享「某个城市的预报」，无法被搜索引擎收录，刷新丢上下文 |
| 2 | 无 OG / Twitter Card、无 favicon、无 robots.txt、无 sitemap | 分享到微信/X 是一张白卡；SEO 为零 |
| 3 | Google Fonts 直连 | 中国大陆首屏字体大概率超时 → FOUT/回退宋体，品牌感在第 1 秒就崩（推断，基于网络环境） |
| 4 | 定位依赖 `navigator.geolocation` + BigDataCloud 逆地理 | 拒绝授权后靠 IP 估算，城市级精度；无手动纠偏入口 |
| 5 | 收藏只存 localStorage，无跨设备、无提醒 | 「收藏此地」落到一个不产生后续价值的空动作 |
| 6 | 霞榜需手动点「加载今日晚霞榜」 | 第一屏最有社交价值的模块默认是空的 |
| 7 | 错误提示只有一句「榜单加载失败：…」 | 无重试、无降级、无「现在能看什么」 |
| 8 | 无加载骨架 | 首次 8–12 秒（实测搜索到出结果约 9–10 s）过程中首屏是「--」和「正在拉取预报…」 |

## 5. 技术审计

### 5.1 结构与可维护性

- `app.js` 单文件 1,400+ 行，渲染/请求/状态/定位/榜单混在一起，无模块边界。
- 无组件层：同一张卡片在 calendar、board、profile 三处各写一遍 DOM 拼装。
- 无测试（现有 `test/` 只覆盖算法与 API 契约，不覆盖 UI）。

### 5.2 性能

| 项 | 实测/估算 |
|---|---|
| 首屏资源 | ≈150 KB 未压缩，gzip ≈40 KB（合格） |
| 字体 | 3 族 6 字重，CJK 子集化后仍可能 1–3 MB（推断，未实测生产环境） |
| 首屏到有数据 | 9–10 s（实测：搜索 → 4 模式 + 空气质量 + 上游 5 点；受 Open-Meteo 限流影响） |
| 免费层额度 | 10,000 次/天、600 次/分钟；一次完整查询≈16 次调用 → **约 37 个并发用户/分钟就会打满**（页面自己写了这段） |

### 5.3 可访问性

- 已有：skip link、`aria-label`、`role="status"`/`role="alert"`、`aria-pressed`、`prefers-reduced-motion` 分支。
- 缺失：`scroll-margin-top`（锚点被 header 遮挡）、focus-visible 样式统一、时间轴 range 的键盘操作说明、图表无文本替代（`layers` 是 `role="table"` 但无可读的 caption）。

## 7. 机会清单（按 ROI 排序）

1. **首屏决策化**：一屏之内给出「今晚 / 明晚」两个数字 + 一个可执行时间窗 + 一个行动按钮。预期收益最大。
2. **天幕升级为「可读的天」**：把真实云层剖面、太阳高度、方位角映射到天幕，让画面本身成为数据（不是装饰背景）。
3. **城市页 + 可分享 URL**：直接解决 SEO 与分享，把「一次访问」变成「一个可被搜索的入口」。
4. **霞榜默认加载 + 地图语义化**：社交传播的抓手。
5. **观景点（Spots）**：回答「去哪看」，这是当前完全缺失的一环（需新数据，标注待实现）。
6. **字体自托管**：去掉 Google Fonts 依赖，中国大陆首屏可救。
7. **六档色阶系统**：一个颜色变六个，分数才有「读数」能力。
8. **中文地名搜索**：内置 200 个常用城市的中英对照词表 + 拼音回退。成本极低，收益极高。
9. **历史命中率页**：仓库已有 `data/glow-dataset.jsonl` 与 `glow-labels.jsonl`，把它做成公开的「成绩单」，是极强的信任资产。
10. **分享卡（OG image）**：每次预报自动生成一张 1200×630 的天幕卡。

## 8. 重构边界（不能丢的 / 可以扔的）

**必须保留**
- 「霞」印章 logo 与六档中文命名
- 程序化天幕（升级，不替换）
- 十一项因素、四模式集合、51 成员分布、通透度、最红时刻、颜色名
- 诚实的局限性表述
- 纯静态、零后端、查询在浏览器端发出、不收集个人数据

**可以扔**
- 竖排装饰字（降级为小尺寸签名）
- 300px 的数字（改为 120–180px + 刻度轨道）
- 「霞历 / 天色 / 霞榜 / 剖面 / 原理」这套内部词汇作为一级导航
- 需要手动点一下才出现的霞榜
- 单断点布局
- Google Fonts 直连
