# 全球朝霞晚霞预测 · 火烧云预报

基于大气光学文献与实时气象数据，预测全球任意地点的朝霞、晚霞与火烧云。

打开页面即可用：搜索任意城市（中文地名），实时查看今明两日共四场（今日朝霞 / 今日晚霞 / 明日朝霞 / 明日晚霞）预测——六档等级（无烧 / 微烧 / 小烧 / 小到中烧 / 中到大烧 / 大烧）+ 霞分 + 通透度 + 五模式一致度 + 置信度 + 剧本类型 + 理由 + 最佳观测窗。另有「今日晚霞榜」（全球 TOP 10 + 全中国 TOP 10）与地点收藏。

## 功能

- **城市搜索**：中文地名搜索（Open-Meteo 地理编码）。已处理同名消歧：中文名查不到大城市时，同时补查「市」后缀变体（如「南阳」→「南阳市」），合并去重后按行政等级 + 人口重排，地级市优先于乡镇；候选行显示所属市。
- **四场预报**：对选定坐标实时拉 Open-Meteo 预报（分层云量、降水、能见度、CAPE 等）+ 空气质量（CAMS 的 AOD、PM2.5），用文献启发式算法评分。
- **结论优先**：每场先给一句话结论（「有一点·小烧 / 有·中烧 / 基本没有」）+ 行动建议（值得专门去看 / 顺便看看就行 / 不用等了）+ 一句主因；置信度翻成白话并说清方向（贴下边界→「把握不大，可能比这更差」；贴上边界→「可能比这更好」）。分数、理由、11 项明细、科学原理默认折叠，点「为什么这样判断？」展开核对。
- **首屏留白**：首次访问、还没拿到位置时不显示任何默认城市，提示用户点一下页面或「定位」；回访用户直接显示上次定位或自己选过的地点。
- **自动定位**：用户第一次点击页面时定位一次（搜索框旁也有定位按钮）。HTTPS 下优先用浏览器 GPS / Wi-Fi 定位；HTTP 访问、拒绝授权或超时时，按 IP 估算到城市。逆地理编码与 IP 定位用 BigDataCloud 免 key 客户端接口。用户手动选过地点后不再自动覆盖。
- **天幕即界面**：首屏天空、云底光照、太阳与水面倒影都由选中场次的评分驱动。云层用 SVG 分形噪声 + 自下而上的漫射光照生成，铺在透视平面上；太阳缓慢下沉、光束摆动、水面闪烁。`prefers-reduced-motion` 时只停闪烁类效果，漂移放慢。
- **霞历**：今明两日四场并排，点哪一场，天幕、时间轴、剖面一起切换。
- **天色时间轴**：以选中场次为中心前后 2.5 小时，可拖动 / 自动播放；拖动走 pointer 事件，手机上横向滑动即可，竖向仍能滚动页面。按当地真实太阳高度角划分 白昼 · 金色时刻 · 火烧云 · 蓝调时刻 · 浅黑 · 黑 六段，天色逐分钟渐变。霞强度曲线 = 评分 × 以高度角 −2° 为峰的钟形曲线，**是示意，不是算法输出**。
- **大气剖面**：11 项因素按它们在大气中的高度排列成层，缺数据的层显示「无数据」。
- **霞榜（每日一次）**：服务器每天北京时间 15:00 运行 `scripts/build-rankings.js`，把 TOP 10 写成 `data/rankings.json`，页面直接读取，访客不再各自调用约 350 次 API；文件缺失或超过 36 小时才退回到手动实时计算。城市落在世界（或中国）坐标带上，叠加此刻的日落经度线；全球 36 座 + 中国 34 座大城市，用与单点查询完全相同的算法批量计算各自下一场晚霞，按评分（同分看置信度）排出全球 TOP 10 与全中国 TOP 10，点行直接查该城市。30 分钟缓存。
- **收藏地点**：localStorage 持久化，可添加 / 删除 / 点击切换。
- **容量说明**：页面内有专区说明 Open-Meteo 免费层限额与推算容量（估算值）。

## 算法

科学依据：Corfidi《The Science of Sunsets》（NOAA/NWS）、SOLA 2013 辐射传输模拟、SkyCandy 6 规则 / SunsetWx / Skyfire 启发式。完整文献见研究笔记。

**v1 条件分（与 `sunset-forecast/predict.py` 一致，parity 测试对照）**：11 项加权评分（权重合计 97）：中高云幕布 30 · 低云 20 · 太阳方向晴空缺口 20（沿日出/日落方位角取上游 50/150/300 km 三点）· 霞时刻降水 10 · AOD 5 · 能见度 3 · PM2.5 3 · 露点差 2 · 风速 2 · CAPE 2；雨后洗净加成 0–3 分；偏南风 + AOD 高扣 5 分；霞时刻降水封顶 40。

**v2 霞分（页面展示）**，2026-10-19 与公众号「super朝霞晚霞预报」493 点榜单交叉对比后引入（详见 `docs/compare-2026-10-19.md`）：

- **几何门控**：火烧云要「幕布 × 缺口 × 低云」同时成立，三项按 0.5 / 0.3 / 0.2 做几何加权（任何一项接近 0 霞分就接近 0）；降水、AOD、能见度、PM2.5、露点差、风、CAPE 只做 ×0.7–1.0 的调制；雨后洗净 +0–5；霞时刻降水封顶 34（最高微烧）。v1 的加权平均会把万里无云算成 60–70 分（中烧），这是主要修正。
- **六档**：≥80 大烧 · 65 中到大烧 · 50 小到中烧 · 35 小烧 · 20 微烧 · <20 无烧。
- **通透度 1–7**：由 AOD、能见度、PM2.5、露点差单独评，和云况分开展示（浑浊 / 灰蒙 / 微霾 / 一般 / 较通透 / 通透 / 极通透）。
- **五模式集合**：云量同时取 Open-Meteo 综合（best_match）、ECMWF IFS、GFS、ICON、CMA GRAPES，一次多点请求拿到本地 + 上游各点，每个模式各算一遍霞分后加权平均（综合 ×2）。置信度看各模式是否落在同一档附近（≥80% 模式在 ±1 档且极差 ≤30 为高）。理由与大气剖面沿用最接近霞分的模式，保证解释和分数一致。
- 降水、能见度、露点、风、CAPE 仍取综合模式；空气质量取 CAMS。
- **v2 缺口**（2026-10-20 起）：只把上游低云 + 0.5 × 中云算作挡光，高云（卷云）不算——照亮云底的光贴着地平线从低空射来，挡住它的是远处的低 / 中云。v1 缺口（用总云量）仍保留在条件分里。详见 `docs/compare-2026-10-20.md`。
- **交叉对比工具**：`scripts/crosscheck/run.js` 批量算一组地点的四场，`scripts/crosscheck/analyze.js` 与外部榜单比 AUC。外部数据不入库。

## 本地运行

纯静态站，无后端、无构建步骤：

```bash
# 方式一：直接用浏览器打开 index.html
# 方式二：本地静态服务器（推荐，避免个别浏览器对 file:// 的限制）
python3 -m http.server 8000
# 然后打开 http://localhost:8000
```

## 更新静态资源时

`index.html` 里的 css / js 引用带内容版本号（`app.js?v=<哈希>`），所以服务器可以对它们长缓存，而文件一改，访客立刻拿到新版。改完 `styles.css` / `app.js` / `algo.js` / `api.js` 后、提交前跑一次：

```bash
node scripts/stamp-assets.js
```

`node scripts/stamp-assets.js --check` 只做检查，版本号过期时退出码为 1。

## 部署

### GitHub Pages

1. 把本仓库推到 GitHub。
2. 仓库 → Settings → Pages → Build and deployment → Source 选择 `Deploy from a branch`，Branch 选择 `main` / `(root)`，保存。
3. 访问 `https://<你的用户名>.github.io/<仓库名>/`。

### Vercel

1. 在 [Vercel](https://vercel.com/) 导入本仓库。
2. Framework Preset 选择 `Other`（纯静态，无需构建命令），直接部署。

### Netlify

1. 在 [Netlify](https://www.netlify.com/) 选择 `Add new site` → `Import an existing project`，导入本仓库。
2. Build command 留空，Publish directory 填 `.`（仓库根目录），部署。

## 数据来源

- Open-Meteo 预报 API（https://open-meteo.com/）：分层云量、降水、降水概率、能见度、气压、风、CAPE、日出日落。
- Open-Meteo 空气质量 API（基于 CAMS）：AOD（550nm）、PM2.5、PM10、沙尘。
- Open-Meteo 地理编码 API：城市搜索。
- 以上均为免费接口，无需注册、无需密钥。免费层限额：600 次/分钟、10,000 次/天（以官方最新政策为准）。

## 局限性（请认真读）

- 本预报为基于已发表文献的**启发式算法**，非官方气象预报；学界目前没有经过同行评审验证的“晚霞颜色指数”模型。预报准确度上限即数值天气预报本身的准确度。
- 大烧 / 小烧分级为**待本地照片校准的操作定义**（方位覆盖 + 持续时间 + 主色 + 余晖），不是既有科学标准。
- 缺数据时页面明确显示“无数据”，绝不编造。空气质量数据为 CAMS 全球域（约 45 km 分辨率、3 小时），局地精度有限。
- 本站为纯静态站，所有查询在浏览器端实时发出，不收集、不上传任何个人数据。收藏与榜单缓存仅保存在浏览器 localStorage。
